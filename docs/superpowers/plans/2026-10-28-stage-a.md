# Stage A (final-a) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (native, per the owner's brief). Steps use `- [ ]`.

**Goal:** Polish, server-verified milestones, streak, Stack skins, share card, invites, hardening and the submission package, merged to main without breaking production.

**Architecture:** Server truth lives in a new `season` Edge Function plus `_shared/chain.ts` (server RPC: verify tx hashes, staker, kickback scan) and pure maths in `_shared/season.ts` (streak, milestones, skins, codes) that vitest covers. `sync` verifies share and stake tx hashes on chain before they count. The app reads `season` after sign-in, caches it per network+address, and never computes unlocks itself. Skins are static CSS generated from the prototype's seeds (`scripts/gen-skins.mjs` → `src/design/skins.css`), applied with `data-kb-skin` on `<html>`.

**Tech Stack:** Vue 3 + Pinia + Vite, Supabase (Postgres, Edge Functions on Deno, pg_cron), Nimiq JSON-RPC, @nimiq/mini-app-sdk 0.2.4, vitest, Playwright.

**Spec:** the owner's FINAL BUILD brief (Stage A section) + `design/Kickback Prototype.html`.

## Global Constraints

- Production must never break: work on `final-a`, merge only with all suites green.
- Never print secrets; service role key only in Supabase; never touch the stake; no fund transfers by me.
- Mainnet and testnet separate everywhere (network column, keys `kb:t:`); preview, dry run, mock never sign in and never earn.
- Never show a dollar amount below $0.01 (no "$0.00").
- Footer copy exactly: "Cosmetic only. Milestones and skins are not money and never become tokens."
- Milestones/streak/invites verified server-side only; client claims are ignored.
- Public stats: signed-in wallets only; stakes/runs/shares only with a confirmed tx hash.
- Pinned bottom action bar visible at 390x844 and 360x740 on Run, Stake, Stop earning, Withdraw, Done.

## Review Focus

1. A share POST with a made-up or someone else's tx hash: stored unverified, never counts (test in Task 2).
2. Same tx hash posted twice (two share ids): counts once (unique verified hash, Task 2).
3. Invite code claimed by a wallet that already staked, or by its own owner: no invite credit (Task 4).
4. Kickback landing with no run inside 24h while a saver was already used this ISO week: streak resets (Task 3).
5. RPC rate limit (429) during a season read: function answers with the last stored state, never 500 (Task 4).

### Task 1: Polish money helpers (pure)

**Files:** Create `src/lib/usd.ts`, `src/lib/ics.ts`, `src/lib/rate.ts`, `src/lib/compound.ts`; Test `tests/polish.test.ts`.

- `usd(nim: number, price: number): string` → `''` when `nim*price < 0.01`, else `'$' + nim2`.
- `buildIcs(events: {start: number, title: string, desc: string}[], uidSeed: string): string` → VCALENDAR, one VEVENT each, UTC `DTSTART:YYYYMMDDTHHMMSSZ`, 10-min duration, `VALARM` with `TRIGGER:PT0M`, CRLF lines.
- `reminderTimes(nextAt: number, intervalH: number, mode: 'next'|'two'): number[]` → 1 time, or every interval for 14 days (28 at 12h).
- `officialRate(...)`: port of the Nimiq staking calculator (from research), `netRate(gross, fee) = gross*(1-fee)`.
- `compoundExtra(stakeNim, apyNet, restakePct, perYear): number` = `(S*(1+i*r)^n − S)/r − S*apy` with `i = apy/n`; r=0 → 0.
- Tests: usd(0.0001)='' and usd(1,0.0157)='$0.02'; ics has `TRIGGER:PT0M`, DTSTART matches the given UTC; 'two' at 12h gives 28 times; compoundExtra(28646, .079, 30, 730) ≈ 27.1.

### Task 2: Server verification of tx hashes

**Files:** Create `supabase/functions/_shared/chain.ts` (server RPC helpers on `createRpc`), `supabase/migrations/20261028120000_season.sql`; Modify `supabase/functions/sync/index.ts`, `_shared/validate.ts`; Test `tests/season.test.ts`.

- Migration: `shares` add `run_id uuid`, `verified bool default false`, `block_at timestamptz`, unique partial index on `(network, tx_hash) where verified`; `events` add `tx_hash text`, `verified bool default false`; `plans` add `min_ready_luna bigint default 10000`; tables `invite_codes(address, network, code unique)`, `referrals(invitee, network, inviter, code, claimed_at, had_stake_at_claim, credited_at)` PK (invitee, network); `kickbacks_seen(address, network, hash, at, luna, from_address)`; `unlocks(address, network, skin, source, unlocked_at)` PK (address, network, skin); `milestones(address, network, key, unlocked_at, proof)` PK (address, network, key); `users` add `skin text default 'spark'`; rewrite `kickback_stats()` (no anonymous fields; verified only).
- `checkTx(tx, expect)` pure: executed, `from == owner`, value == amount, `to` == contact (send) or staking contract (restake/stake). Tests: tampered from/value/to → false.
- `sync` POST share: validate, then verify with RPC `getTransactionByHash`; not found yet → stored `verified=false` (rechecked by `season`). POST event `stake|add_stake|run_done` may carry `tx_hash`; verified the same way.

### Task 3: Season maths (pure)

**Files:** Create `supabase/functions/_shared/season.ts`; Test `tests/season.test.ts`.

- `streak(kickbacks: number[], runs: number[], now: number)` → `{ current, best, savers, hist: ('ok'|'missed'|'saved'|'pending')[] }`. A kickback (batched within 10 min) is ok if a verified run lands in `[at, at+24h]`; still inside 24h and no run → pending (doesn't break); else a saver if that UTC ISO week's saver is unused → saved; else missed → current resets. `savers` = 1 if this week's saver unused.
- `milestonesFrom(facts)` → keys `first_stake, first_kickback, first_share, ten_runs, hundred_shared, streak_30, invited_staker`. `hundred_shared` = verified send+restake ≥ 100 NIM; `streak_30` = best ≥ 60.
- `skinsFrom(keys)`: spark always; kick←first_stake, bounce←first_kickback, rally←first_share, surge←ten_runs, legend←hundred_shared|streak_30.
- `inviteCode(rand: Uint8Array)` → `KICK-XXXX` (Crockford base32, no 0/O/1/I).
- Tests: streak cases (shared in 24h, missed, saver once per week, pending), milestone/skin mapping, code format.

### Task 4: `season` Edge Function

**Files:** Create `supabase/functions/season/index.ts`; Test `e2e/season-api.mjs`.

- GET (session): recheck up to 10 unverified shares; scan the user's newest tx pages (≤3, stop at a known hash) for kickbacks from the pool reward addresses (`pool_stats` + current delegation); staker via `getStakerByAddress`; credit referrals whose invitee now stakes and had no stake at claim; upsert milestones + unlocks (never removed); return `{ code, milestones, unlocked, skin, streak, invites: {claimed, staked}, paused:false }`. RPC errors → last stored state.
- POST `{ skin }`: only an unlocked skin. POST `{ ref }`: one inviter per wallet, not your own code, records `had_stake_at_claim` from RPC.
- e2e: generated key signs in on testnet; spoofed share hash stays unverified and unlocks nothing; skin not unlocked → 400; own code → 400; second claim → 409.
